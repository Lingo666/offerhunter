# 三个带学片段

以下代码均为虚构的微型练习，用于示范教练在什么地方该停下来等回答。带学时换成学员当前项目里能核实的代码。

## 先让学员预测一个值

**教练先问**　待办清单里有两项未完成、一项已完成。点击「只看已完成」后，关掉这个开关，你预计会出现几项？先给判断。

**学员**　“应该只剩一项，我以为过滤时把另外两项删了。”

**这时再看代码**

```python
visible = [task for task in tasks if task.done] if only_done else tasks
draw_list(visible)
```

**解释**　这里开启开关会新建一份用于显示的列表，原来的 `tasks` 仍保留三项。关掉开关时，传给 `draw_list` 的是原列表。把图上的一条箭头补全为“清单状态 → 可见列表 → 绘制”。到这里，让学员自己指出把判断从“一项”改为“三项”的那行代码。

## 当两个原因能解释同一个现象

**教练先问**　计时器设置为 2 分钟，却在 2 秒后响了。是读取设置时单位错了，还是启动计时器时传错了？只凭响铃时间，你能确定哪一处？

**学员**　“我会先看启动计时器时收到的值。”

**这时再看代码**

```python
minutes = int(settings["duration_minutes"])
timer.start(seconds=minutes)
```

**解释**　代入 `duration_minutes="2"`，读取后得到 2 分钟，而调用处把同一个数当作 2 秒传入。一个能验证改动的检查是用这个设置调用入口，记录计时器收到的 `seconds` 是否为 120。若现场只替换了计时器并记录参数，就只能证实传参，实际响铃时间还需运行观察。

## 用一个新条件收课

假设学员读过一段按加入顺序播放歌曲的代码，已经确认“手动下一首”和“自然播完”最终都调用 `advance(reason)`。

**教练问完就停**　“现在希望单曲循环只对自然播完生效。仅改负责绘制播放按钮的代码，能覆盖这个需求吗？你会去哪里找一个可以验证判断的交接点？”

**供教练在学员回答后使用**　如果两个入口传入不同的 `reason`，就让学员在实际处理该参数的地方分别代入两个值，观察选中的下一首。若手边的代码没有区分原因，先让学员指出信息在哪个交接点丢失。能在新条件下独立指到证据才记为“换题独立完成”。
